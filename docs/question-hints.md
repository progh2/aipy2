# 연습 문제 힌트 작성·검토 규칙

문항 지문·정답·해설은 `tools/web/questions.py`와 `later_units.py`에서 관리합니다.
화면에 제공하는 두 단계 힌트는 `tools/web/question_hints.json`에서 관리합니다.
이 파일은 문항 ID와 지문을 함께 저장합니다. 문항을 추가하거나 지문·순서를 바꾸면
힌트도 검토해야 하며, 불일치 시 빌드가 실패합니다. 기존 문항 선언의 `hint` 인자는
이전 형식 호환용입니다. 새 힌트의 편집 위치로 사용하지 않습니다.

- **힌트 1 — 개념·접근 방향:** 그 문제를 풀 때 필요한 원리를 직접 설명합니다.
  ‘위젯 도감을 확인하세요’, ‘예제를 보세요’ 같은 참조 지시만 쓰지 않습니다.
- **힌트 2 — 구체적 단서:** 힌트 1을 적용할 비교 기준·추적 단계·경계 조건을 제공합니다.
  함수·위젯 이름을 묻는 문제에서는 이름을 그대로 쓰거나 조각으로 풀어 주지 않습니다.
  출력 예측에는 계산 결과를 쓰지 않고 계산 순서를, 구현에는 완성 코드 대신 검토할 조건을 줍니다.
- **정답 예시와 해설:** 정답·완성 코드·최종 계산값은 이 영역에서 제공합니다.
  해설을 힌트 2로 재사용하지 않습니다.
- 같은 주제라도 문항별 조건에 맞는 힌트를 씁니다. 두 힌트를 읽은 뒤에도
  학생이 비교·계산·코드 작성·판단 중 하나를 직접 해야 합니다.
- 문항 번호·정답을 바꾸지 않고 힌트만 고치면 기존 학습 기록이 유지됩니다.

예: ‘설명 글자를 표시하는 tkinter 위젯 이름’의 힌트 1은 ‘입력받지 않고 설명이나
상태를 보여 주는 표시용 요소’, 힌트 2는 ‘이름 입력칸 옆 안내문과 타이핑하는 영역의
차이’입니다. 정답 이름은 힌트에서 제공하지 않습니다.

2026-09-21: 1단원 60, 2단원 70, 3단원 44, 4단원 39문항의 힌트를 모두 검토했습니다.
`verify.py`는 모든 문항의 힌트 존재·지문 일치·해설 분리와 짧은 답의 직접 노출을 검사합니다.
의미상의 정답 노출 여부는 편집자가 지문·선택지·정답과 함께 읽고 검토해야 합니다.
